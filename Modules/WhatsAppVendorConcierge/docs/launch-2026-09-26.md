# Launch changes — 26 September 2026

## Architecture and controls
- Global Store-managed Delivery: super-admin control at `/admin/whatsapp/store-managed-delivery`, linked from Vendors and Operations Centre. Supports Grocery, Shop, Food and Pharmacy; excludes Parcel/Rental. Explicit global on/off overrides subscription delivery settings and persists to existing stores; new/edited stores inherit it. An absent setting preserves upstream behavior.
- Core changes: `app/Models/Store.php` accessor and saving hook, plus generic `app/Services/StoreManagedDeliveryPolicy.php`. Both contain GEMINI-MYTJ markers and are registered in `scripts/core-patches.json`. Core does not depend on the concierge module. Global settings UI is module-contained. Reapply the marked hooks and service when upgrading upstream.
- Support requests use a prefilled link to +2347049147825. They no longer create a takeover or pause onboarding/AI. Explicit administrator takeover and technical escalation remain available. Historical support tickets are not silently closed.
- Inclusive greetings and operating/dispatch address wording welcome online-only and home-based businesses. A real location and supported zone remain necessary.
- “Show my shop details” has a deterministic route so the registered owner's details do not depend on AI availability.
- Audited, idempotent access notices: `php artisan whatsapp:vendor-access-notice` previews; `--force` sends once per channel/store for this launch. Email contains login details, dashboard guidance, Home Screen instructions, support link and mobile-app update. No passwords are sent. WhatsApp free-text requires a linked, unblocked contact and a recent inbound within 24 hours; excluded recipients are explicitly reported. Uncertain transport outcomes require manual verification instead of automatic resend.

## Deployment storage
`.mytijaara-releases` contains incoming deployment packages and rollback journals. Old incoming packages caused file-count (inode) growth; this is distinct from the InnoDB database engine.

Successful deployments now write a completed marker, then run `scripts/prune-releases.php APP_ROOT --force`. The existing Laravel scheduler repeats cleanup at 03:20 daily. Dry run is the default without `--force`.

Cleanup locks against deployment, validates the release/application paths, follows no symlinks, removes only completed incoming packages, and retains at least the latest two completed rollback journals plus journals younger than seven days. Unmarked, failed or unfamiliar release directories are preserved for investigation. Runtime uploads, database files, credentials, sessions and current application code are not cleanup targets. Legacy completion markers must be added only after verifying the corresponding GitHub runs succeeded.
